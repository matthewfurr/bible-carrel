# Bible Carrel

Bible Carrel (named 2026-11-16, for a two-year Reading Through Scripture group) is a native macOS and iPhone app for reading through the Bible, with phrase-level highlights, linked notes, bookmarks, and an LLM study assistant that runs on Apple's on-device model by default and on Anthropic, OpenAI or OpenAI-compatible endpoints when you add a key. User data syncs through the private iCloud database.

Design: [docs/superpowers/specs/2026-10-26-reading-through-scripture-design.md](docs/superpowers/specs/2026-10-26-reading-through-scripture-design.md)
Current plan: [docs/superpowers/plans/2026-11-12-milestone-9-reader.md](docs/superpowers/plans/2026-11-12-milestone-9-reader.md)

The public site's source is in `site/` (preview with `npm --prefix site run dev`, check with `npm --prefix site run check`; see `site/README.md`).

## Prerequisites

- macOS 26 with Xcode 26 installed. If `xcode-select -p` still points at the Command Line Tools, either run `sudo xcode-select -s /Applications/Xcode.app` once or let the scripts set `DEVELOPER_DIR` for you.
- Apple Intelligence enabled, for the on-device model (later milestones).
- The developer team (Team ID `SFQ7B3J933`) added in Xcode › Settings › Accounts. The app is signed with it automatically; `-allowProvisioningUpdates -allowProvisioningDeviceRegistration` lets a command-line build fetch the profile and register this Mac.
- Signed in to iCloud on this Mac, for sync, with Passwords & Keychain on if API keys should travel too.

## Building the Bible database

The Bible text comes from [bobuk/holybooks](https://github.com/bobuk/holybooks), pinned to one commit. The generated database is not committed; build it once:

```bash
bash Scripts/build-bible.sh
```

This fetches the source into `~/Library/Caches/ReadingThroughScripture/` and writes `Build/bible.sqlite` (about 82 MB: eight English translations, the cross-references, and the Library's people, places and events). Warnings about Sirach and the stray `NAH` folder are expected.

The section headings and book titles come from eBible.org: the Berean Standard Bible's USFM (its `\s1` and `\s2` headings, public domain) and the KJV's (its own book titles). `Scripts/fetch-ebible.sh` downloads the two zips and checks each against a pinned SHA-256 digest; if eBible changes a file it stops and tells you to check it and re-pin. The importer writes them into `bible.sqlite` as the `heading` and `book_title` tables. Schema version 3 gave each translation its own full-text index, built from the words as written (not stemmed), with a word list beside it that the search's "did you mean" reads; see Search. Schema version 4 adds the `cross_reference` table, one row per link (the source verse, the target's start and end, and its votes), indexed from both ends so what a verse points to and what points to it are each a lookup; see Verse panels. Schema version 5 adds the Library's data (see The Library): people, places, events, the links from each to its verses, family links, Easton's dictionary entries and each book's writers, kept by the data's own ids, never by name. `Scripts/ensure-bible.sh` rebuilds the database when it is missing or was built with an older schema, and the apps' "Bundle Bible database" build phase runs it, so a plain build after pulling picks the headings up by itself.

## The app icon

The icon is `Apps/Mac/ReadingThroughScripture/AppIcon.icon`, an Icon Composer document (Liquid Glass, with Light, Dark, Tinted and Clear variants). Edit it by opening it in Icon Composer and saving; the app folder is a synchronized group and `ASSETCATALOG_COMPILER_APPICON_NAME = AppIcon` names it, so the build picks the change up with no project edit. Xcode compiles it into `Assets.car` and derives the `AppIcon.icns` from it.

## Running the app

Open `ReadingThroughScripture.xcworkspace` in Xcode and run the `ReadingThroughScripture` scheme, or build from the command line:

```bash
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcodebuild -workspace ReadingThroughScripture.xcworkspace -scheme ReadingThroughScripture -configuration Debug -derivedDataPath Build/DerivedData -allowProvisioningUpdates -allowProvisioningDeviceRegistration build
```

The app's "Bundle Bible database" build phase runs `Scripts/ensure-bible.sh` (which calls `Scripts/build-bible.sh` when `Build/bible.sqlite` is missing or out of date) and copies the database into the app bundle. The built app is at `Build/DerivedData/Build/Products/Debug/ReadingThroughScripture.app`.

There are two builds, and they never share anything:

- **Debug** (what Xcode and the command above build) has the bundle ID `com.matthewfurr.ReadingThroughScripture.dev`, its own iCloud container (`iCloud.com.matthewfurr.ReadingThroughScripture.dev`), its own store, preferences, key-value store and keychain items. It is for development and starts as an empty copy.
- **Release** is the app you read in, bundle ID `com.matthewfurr.ReadingThroughScripture`, container `iCloud.com.matthewfurr.ReadingThroughScripture`. `Scripts/install-app.sh` builds it with the same provisioning flags (`-configuration Release`), quits the installed copy if it is running, and installs it as `/Applications/Bible Carrel.app`, so the Dock and Finder show the app's name (the build itself keeps the file name `ReadingThroughScripture.app`, and the running process is still `ReadingThroughScripture`). A copy left under the former name, `/Applications/ReadingThroughScripture.app`, is removed once the new one is in place. For now it syncs through the container's Development environment, which builds its schema as records arrive; moving to Production later needs a fresh store and a copy. Never use "Reset Development Environment" in CloudKit Console while the Release build syncs there: it would erase your notes from iCloud.

The installed app keeps its store at `~/Library/Application Support/ReadingThroughScripture/Sync/iCloud.com.matthewfurr.ReadingThroughScripture-Development/Markup.store`, with its daily backups in `Backups/` beside it. Do not copy a store file between Macs; let iCloud bring the notes.

Two launch arguments help with testing. `-storeName Second` opens `Second.store` beside the main store (1 to 32 letters, digits or dashes; anything else falls back to `Markup`): a second, empty store that mirrors the same cloud database and stands in for a second device on one Mac. Its backups go to `Backups-Second/`. In a Debug build only, `-syncProbe` makes one change once the store is ready and logs `probe done: <argument>` to the `sync` log: `bookmark:GEN.1.1` toggles that bookmark, `note:GEN.1:<text>` sets the body of the chapter note on Genesis 1, and `deleteNote:GEN.1` deletes it. `-forceSyncAttention YES` (Debug only) shows the toolbar's sync notice as if sync had failed for a day. `-planProbe make | large | clear` (Debug only, both apps) saves a small stand-in reading plan, or an 86-week one with most of its readings ticked, or removes them, once the store is ready, and logs `plan probe done: <form>` (`plan probe already there` when the plan was stored already). It **refuses the main store**: it does nothing, and logs `plan probe refused: never in the main store`, in the store named `Markup` (in any capitals) of the Debug or Release container, or in the default store with sync off, so a stand-in plan never reaches the notes you read from; use it with `-storeName` or in a separate identity. `-versionProbe` (Debug only, both apps) stands in for an editing sitting and for each choice on a kept version, once the store is ready: verbs joined by `|`, run in order (`note`, `type`, `use`, `keepBoth`, `discard`, `restore`, `seed`, `seedOrphan`, `clear`), logging `version probe done: <argument>` or `version probe failed: …` to the `sync` log. **Both probes refuse the main store** (the store named `Markup`, whatever its capitals, and the default store with sync off), so a stand-in change never reaches the notes you read from. They do not refuse a `-storeName` store of the Debug app, and such a store shares the `.dev` iCloud database with the phone's Debug app: for a clash rehearsal use a separate identity (the rehearsal one, `com.matthewfurr.ReadingThroughScripture.rehearsal`), never `.dev`.

```bash
open -n Build/DerivedData/Build/Products/Debug/ReadingThroughScripture.app --args -storeName Second -syncProbe bookmark:GEN.1.1
```

The sync log: `log show --last 5m --predicate 'subsystem == "com.matthewfurr.ReadingThroughScripture" AND category == "sync"'`.

The front page is a contents page with a book pane beside it (see The Library below): every book of the translation under its Testament, set at your page text size (⌘T, ⌘+ and ⌘−), with the book being read chosen and its chapters in the pane, whose numbers follow the same size. Drag the divider between them to make the pane wider (more chapters across); a double-click on it returns the pane to its narrowest. The width is kept on this Mac, not synced. A ring around a chapter number means the chapter has a highlight, note or bookmark; the ring is in the colors of its highlights. Click a book to see its chapters, double-click it to open it. The field in the toolbar (⌘F) searches the books; type a reference such as "rom 8" and Romans is chosen with the 8 ringed, and Return opens it.

Keyboard: ⌘K go to a passage, search, or run one of its 33 commands (the menus' own, page styles and appearances, Switch Translation…, Copy Link to This Chapter and more; each shows its key; it opens empty every time), and in it Tab and ⇧Tab narrow to one kind of result and ⌃Tab and ⌃⇧Tab step where Scripture is searched; ⌘+ and ⌘− make the text larger and smaller; ⌘[ and ⌘] back and forward; ⇧⌘H home; on the front page, Tab moves to the contents, the arrows choose a book (up and down within a column and on to the next, left and right across columns), Return or Space moves into the pane's chapters, where the arrows move between chapters and Return opens one, and ⌘F searches the books; Esc leaves a People, Places or About view for the contents; ⌥⌘← and ⌥⌘→ previous and next chapter; ⌘T Text & Layout; ⌥⌘N show or hide the notes column; ⇧⌘N the Notes browser; ⌥⌘P the reading plan; ⇧⌘E export notes; ⌘, settings.

In the reader, a click on a verse's words or number selects the verse and opens the markup menu for it, every time, just below the verse (or just above it when there is no room below), not over its words; for a selection taller than the window it opens beside the pointer instead; a drag, a double-click and a click inside a highlight open the same menu, and a right-click works as before. With the menu open, a click anywhere else only closes it and deselects; the next click selects. Esc closes the menu and keeps the selection, so the keys below can act on it; a second Esc clears it. With the reader focused (it takes focus when a chapter opens, when a note is finished and when the palette or the sheet closes) the keys act on the selected verse: J and K select the next and previous verse (held, they walk on), ⇧J and ⇧K grow or shrink the selection, 1 to 9 highlight it in the nth color, 0 takes the color off, N adds or edits its note (and shows the notes column), B bookmarks its verse, C opens Compare Translations and R Cross-References for it (see Verse panels), ← and → turn chapters. Held, a number, 0, N, B, C or R acts once; J, K, ⇧J, ⇧K and the arrows repeat. While ⌘K is showing or a note is being edited the reader's keys do nothing, so what you type there never acts on the verse. ⌘/ (or `?` in the reader, Help › Keyboard Shortcuts, or "Keyboard Shortcuts" in ⌘K) opens a sheet that lists every shortcut in the app and filters by what you type.

The chapter is set like a printed page as far as each translation's text allows. A prose paragraph indents its first line, except the chapter's first paragraph and one that follows poetry; each line of poetry is its own paragraph and hangs under its first word when it wraps; a verse that ends a stanza is followed by half a line of air. The bundled translations mark these differently: WEB marks paragraphs and stanzas (Matthew 5 indents its paragraphs and hangs the Beatitudes as poetry), ESV marks poetry lines but no paragraphs or stanzas (Psalm 119 hangs, Matthew 5 is one paragraph), and the KJV sets Psalm 119 as one paragraph per verse. The text has "Lord" in title case in every translation, so nothing is set in small caps.

The reader shows one chapter at a time. A book-long scroll was tried in this milestone and dropped: TextKit 2 laid out again, from estimated heights, what had scrolled above the screen, so the page drifted; one chapter keeps every line in place (Psalm 119 opens in well under a second on both apps). Chapter 1 opens on the book's title and subtitle; each later chapter opens straight on its text, in Lectern on its drop numeral, and the running head names it from the top. As the opening scrolls away a running head takes over, pinned at the top on the Mac and in the bar's title on the iPhone: it names the chapter, and is hidden only while chapter 1's title is in view. The thin line in the accent under it grows through the chapter and is full at its foot; it is empty when the chapter fits the window. Everything that says "this chapter" (the window title, the notes column, Notes in This Chapter, Ask About This Chapter) follows the open chapter, and so does your place. A click on the running head goes back to the book's chapter grid.

Scrolling stops at the chapter's end, where its links go back or on: "Previous: John 2" at the leading edge and "Next: John 4" at the trailing edge, one above the other when they do not fit side by side. At a book's ends they name the neighboring book's chapter ("Next: Acts 1" at John 21). On the Mac they are revealed as the chapter's foot scrolls into view; Previous and Next (⌥⌘← and ⌥⌘→) do the same from the keyboard.

The page comes in four styles, set in Settings › Reading: Printed (the default, in Literata), Lectern, Study and Classic. Beside the style, Reading sets the font, size (14 to 28 pt), line spacing, column width, layout (paragraphs or a verse to a line), verse numbers, section headings, justification and appearance: System, Light, Sepia or Dark. On the Mac ⌘T (View › Text & Layout, or the toolbar's `textformat.size`) opens the same set in a popover over the page. On the iPhone the reader's `ellipsis` menu holds page style, size, line spacing and appearance, with More Settings… for the rest. Section headings are the Berean Standard Bible's, borrowed for every translation except the CPDV (whose numbering differs); the KJV shows its own book titles. Page style, font, layout, verse numbers, section headings and justification sync through iCloud; size, spacing, column width and appearance stay with each device.

The app remembers your place, the chapter and verse you are reading, and reopens there on this Mac and your other devices. Reading moves it, within a chapter and from one chapter to the next: a chapter chosen on the front page, Previous and Next, and a reference or book in ⌘K. Looking something up does not: a note, highlight or bookmark from the Notes browser or ⌘K, a verse found by searching in ⌘K, and Open on a verse in an assistant reply show the passage, and Back (or Home) returns you to your place at the verse you left. One in the chapter you are reading scrolls there and keeps your place too, with Back to return to it, until you scroll five lines or more on from where it landed (up or down); then it becomes your place. In another translation it stays a lookup however far you scroll. If you read on from the passage with Previous or Next, or choose Go › Read From Here, it becomes your place. Quitting mid-lookup reopens at your place, not the passage.

### The book thumb and the chapter switcher

The reader shows one chapter at a time; scrolling stops at its end. Chapter 1 opens on the book's title; every later chapter opens straight on its text, and the running head (the bar's title on the iPhone) names it from the top. Along the right edge a book thumb holds the whole book as a ruler's edge: a tick per chapter, every fifth longer, the chapter you are reading marked in the accent, the ticks swelling under the pointer or finger. On the Mac it appears when the pointer nears the right edge and for a moment after you land on a chapter (never for a scroll), stays two and a half seconds and fades out slowly; drag it to choose a chapter, and a loupe beside the pointer shows the chapter number in a disc of clear glass: the page shows through its middle and bends at its rim. Letting go opens that chapter at its start. On the iPhone the thumb is the right 28 pt of the screen: long-press there (0.3 s) and drag; you feel a tap as it takes and one for each chapter passed, the loupe stands to the left of your finger, and the margin's note and bookmark marks stand aside until you lift. The system scroll indicator is hidden. VoiceOver gets one adjustable "Chapter" element.

On the iPhone a stack of chapter cards (the chapter switcher) waits just past each end of the page. Pull up past the end of a chapter, or down past its top, and the cards come into the space the pull opens; let go once you feel the tap (about 110 pt of pull) and the page rests there with the cards in view. Reaching an end while scrolling very fast (over 5,000 pt/s as the page meets it) opens them too. Nothing on the page is covered. The front card shows the next chapter's number (the previous one, at the top) under "Chapter", and its opening verses with their numbers, set as your page style sets the page. Flick anywhere on the page the way you pulled to go further, flick back to return, and tap the front card to open its chapter: forward at that chapter's start, the previous chapter after a pull at the top at its end, further back at its start. Past a book's last chapter the stack ends on a title card for the next book (before its first, the previous book), which you feel arrive with a firmer tap. The cards stay until you tap one or tap the page. The numbers (`ChapterSwitcher.pullThreshold`, `flickSpeed`, `arrivalSpeed` and `flickTravel`, `LoupeLens`'s blur, veil and refraction, `PhoneChapterTextController.switcherSpring`, `thumbEdgeZone` and `thumbHold`, `ThumbHaptics.detentIntensity`, `ThumbRevealTracker.linger`) are to be tuned on a device.

## Markup

Select text and right-click for the markup menu: a row of color swatches (plus `+` to add a color), Add Note, Bookmark Verse, Compare Translations and Cross-References (see Verse panels), Copy, Copy with Reference (`“text” — Matthew 5:3 (ESV)`), Copy Link (see Links), Share, and Ask About This Passage. A note added without a color anchors to the phrase with a dotted underline; a color can be added later from the same menu. Bookmarks mark the whole verse with a glyph in the left margin. Highlights made in one translation show as a dashed underline on the whole verse when reading another.

A new color (the `+` in the swatch row, or Settings › Markup) is kept light enough in light mode, and dark enough in Dark Mode, for the text over it to stay readable: a pick outside that band moves to its nearest edge at the same hue, so a navy becomes a pale blue in light mode and a deep blue in Dark Mode, and a Settings well set to black lands on a gray.

A chapter with notes of its own (a note on the chapter, such as Add as Note on a chapter conversation) shows a paper mark at the right of its opening line (and of the running head, when it is the chapter in view) with the count inside; click it to show the notes column, where they come first. The notes column is the window's inspector on the right (drag its edge to resize, ⌥⌘N to hide). It lists this chapter's notes and, as one-line rows, its highlights without notes. A first click on a row selects it and scrolls to and outlines its highlight; a second click, or Return, edits the note (or starts one on a highlight). Escape or ⌘Return finishes. With the column focused, ↑ and ↓ move between rows and Delete deletes. Every delete, from the column, the selection menu or the Notes browser, can be undone with ⌘Z.

Highlights, notes and bookmarks are kept in the synced store (see Sync and backups).

### Links

A passage has a link, `bible://<book>[.<chapter>[.<verse>[-<verse>]]][?translation=<ID>]`, with the book as the app's three-letter code in any case: `bible://jhn.3.16`, `bible://jhn.3.16-18`, `bible://rom.8`, `bible://jhn` (John 1), `bible://1co.13.4-7?translation=KJV`. A link written by hand may name the book instead, but only as a book's whole name, short name or alias (`bible://John%203:16`, `bible://john.3.16`): a beginning of one (`bible://ma`) is not a link, nor is a name of one or two letters with no chapter (`bible:is`). Copy Link in the selection menu (on the iPhone behind the chevron) copies the link to the selected verses, with no translation; pasted as plain text it is the URL, and into an editor that takes rich text it is the reference carrying the link. Both apps answer these links: opening one shows the passage as a lookup, so Back returns to your place, and a link that cannot be read changes nothing. A `bible://` link typed or pasted into a note is a link in the rendered note. The Debug builds answer and copy `bible-dev://` instead, so a link in your own notes never opens the Debug copy. Nothing is registered with route.bible and nothing is fetched from it.

## Verse panels

Select a verse (or a run of verses in one chapter) and two panels are one action away, in the context menu on the Mac, behind the chevron of the selection menu on the iPhone, and on the Mac by C and R. They are separate panels, and neither takes your place: a row opens as a lookup, and Back returns.

- **Compare Translations** (C) shows the verse in the translation you are reading, marked "reading", and then in the translations of your compare set, in the translation list's order. Part of a verse counts as the whole verse, and more than five verses shows the first five and says so. A translation that lacks the verse says "Not in the ERV." and cannot be opened; the CPDV numbers the Psalms differently from the others, so in Psalms its row says it may show a neighboring verse. A click on a row shows the verse in that translation; the row marked "reading" only closes the panel. The foot has Ask About the Differences, which opens the assistant on the verses with the Compare translations prompt and exactly the rows shown (the on-device model still receives three at most), Copy (every row as Copy with Reference writes it, one to a line), and Translations…, the checklist of the compare set. The same checklist is in Settings › General under Compare with, and the set travels between your devices as one synced preference, `compareTranslationIDs`. The Compare translations prompt run from the assistant's own list sends the compare set too, in the same order, and the default four when the set is empty.
- **Cross-References** (R) is about the selection's first verse, and the chevrons beside its reference step through the chapter's verses. It lists what the verse points to and which verses point to it, each strongest first by the data's votes: six of the links with four or more votes, then Show all with the count. A link that runs into another chapter is shown as the part in its first chapter. A row shows the reference over its opening words in the translation you read; a click shows the passage inside the panel, with Back and Open. Ask About These opens the assistant on the verse with one question the app composes from the verse and the passages listed (nothing is stored in Settings › Prompts), and the foot credits OpenBible.info.

On the Mac each is a popover on the selection's first line; Esc or a click outside closes it and the selection stays; it also closes when the page scrolls under it or its text is laid out again (a new text size, the notes column, a resized window). On the iPhone each is a sheet at half height or full. At large text sizes the foot of each panel wraps and the credit stays on screen. The links come from OpenBible.info's `cross_references.txt` (the 2026-09-21 file, 341,282 links with at least one vote, drawn chiefly from the Treasury of Scripture Knowledge), written into the database at build time; the app never goes to the network for them.

### The cross-reference data

`Scripts/build-bible.sh` runs `Scripts/fetch-crossrefs.sh`, which downloads the file, checks its SHA-256 digest against the one pinned in the script (`d18f0cde…44f8`) and stops, telling you to check it and re-pin, if it differs, as `fetch-ebible.sh` does. It tries OpenBible's own address first and then a mirror of the pinned file (trekhleb's repository on GitHub), because OpenBible has since put a newer file at its own address; an uncached build therefore downloads and rejects that newer file before it uses the mirror. The file is cached in `~/Library/Caches/ReadingThroughScripture/crossrefs/<first twelve characters of the digest>/`, never committed, and a second run prints that folder at once, after checking the cached text against the digest again; if it no longer matches, the script says so and fetches it again. Both downloads have a time limit. The script reads its one file, `cross_references.txt`, out of the archive without unpacking it (and refuses one larger than 64 MB), and the mirror is named by commit, not by branch, so it cannot move. The importer records the digest in the `meta` table as `crossrefs_sha256`. It prints how many links it wrote (`links: N`, beside its verses, books and warnings), and the build fails if a cross-reference file was given and no link was kept from it, so a re-pin to a file in a new shape cannot quietly produce an empty table.

## The Library

The front page on the Mac is the Library's contents page, and the iPhone's Library (the `books.vertical` button) lists the same books. A book opens to its chapters and to four icons: BibleProject's overview video, People, Places and About, each available for any of the 66 books (the Apocrypha has none of the three; the data does not cover it).

- **The contents page (Mac).** Every book under its Testament and its group (Law, History, Poetry, …), in as many columns as fit. The book being read is chosen when it opens, with its chapters in the pane at the right; click to choose another, double-click to open one. Tab goes to the contents, the arrows move between books and columns, Return or Space moves into the pane. ⌘F is the toolbar's search of the books; ⇧⌘H comes back here from anywhere, with the book being read chosen.
- **Rings.** A chapter with a highlight, note or bookmark has a ring around its number on both apps, one segment for each highlight color in it (the first six). A chapter marked without a color has a plain gray ring.
- **People.** Everyone the data names in the book, each with a count, in one of two orders: **Most named** (most verses first) or **A to Z**, a switch at the head of the list that this device remembers for every book. A person's page opens with their name as a title and the data's own description under it ("son of Boaz"; nothing where the data has none), then their facts in an aligned list: father and mother (each opens that person), what else they are called, when they lived (with dates on), how many verses name them here and in all, and the size of their family ("8 partners, 21 children"). The dictionary's entry (Easton's Bible Dictionary, 1897) shows its whole first paragraph, cut at a sentence end only past about ten lines; Show more opens the rest and Show less closes it. On the Mac the family is a drawn tree: grandparents, parents, the person with their siblings and half-siblings, then each partner (and each mother the data names who is not a partner) with her children under her, and the children whose mother is not named together at the end. When a generation is too wide for the column it folds into a count ("7 siblings", "4 more") that opens in place, so the tree never scrolls sideways. Tab reaches it, the arrows move between names, Return opens one and Space opens a fold. On the iPhone the family is a line down the timeline's rail (grandparents, parents, the person, the siblings under the parents) with the household branching below. Every name opens that person. The app never says "son", "brother" or "eldest": the data records neither sex nor birth order. The verses, in this book and in the other books they appear in, read one line per chapter ("3   1-2, 5-6, 8-10, 12, …"), the first twelve chapters and then the rest on request; a place's page shows its verses the same way. A click on a run of verses shows them in place (a popover on the Mac, a page on the iPhone) with Open; on the Mac Tab reaches each line, the arrows move from run to run and Return opens one. **Open goes to the reader and Back returns to the same person.**
- **Places.** Apple's map framed to the book's places, one pin for places the data puts at the same spot, with a list beside it (a sheet on the iPhone). The map needs a connection for its tiles; the pins and list do not. Places the data cannot locate sit under "Not on the map"; a position the data marks as rough is called approximate. The list comes in three orders, a switch at its head that this device remembers: **Most named**, **A to Z** and **By chapter**. By chapter lists each chapter that names a place under its heading; choosing a heading (or, on the Mac, ← and → between chapters, with ↑ and ↓ walking the places across them) makes it the chosen chapter and the map follows, framed to the chapter's places with the book's other places as small dots; Back from a passage returns to the same chapter. A place chosen from a pin shared with others puts its own name on the pin, and on the iPhone the chosen pin and chapter are kept clear of the sheet.
- **About.** The book's name and subtitle, then its facts in an aligned list: Testament and group, chapters and verses, the writers the data names ("Attributed to", "by tradition"), the years it spans, and the five most named people and places ("and 347 more" opens People). Under them the book's timeline in the order of history: a life is one row ("lived 930 years · to 3074 BC") with its birth and death folded in, three or more lives in a row fold into one line that Show opens, and an event with children heads a group, as the Flood does in Genesis. On the Mac a chart of the book's whole span to scale sits over the rail, with a band over the rows on screen; click the chart and the list moves there. The iPhone has the rail alone. Settings › General › Library › Show dates off removes every year, the chart and the spans; lengths stay. Two corrections are made to the data when the Bible database is built (`BibleImporterCore/TheographicCorrections.swift`): Theographic's "Death of Moses" had Genesis 34:1 beside Deuteronomy 34, and "Birth of Job" and "Lifetime of Job" had Genesis 46:13 (Issachar's son Job, tied to Job of Uz); each is checked when the data is built and warns when a newer file no longer needs it.
- **Dates.** Years follow a traditional chronology (Ussher's, as worked out by Floyd Nolen Jones, which puts Creation at 4004 BC). A notice says so the first time one is shown; Settings › General › Library turns every year the app writes off. A dictionary entry's own words may still mention one.
- **By name.** ⌘K and the iPhone's search find a person or a place by its name or an "also called" name and open its page for the whole Bible.
- **Coming back.** Back and Home (and the iPhone's way back at the top left) return from a passage opened here to the same book, view and person or place. Reading on with Next or Previous, or Read From Here, makes the passage your place instead. The page's scroll position and the map's zoom are not kept, and closing the Library on the iPhone, a plain Home on the Mac, or quitting forgets the page.

The data is Theographic Bible Metadata (CC BY-SA 4.0), five tables (`books`, `people`, `places`, `events`, `verses`) at one pinned commit. `Scripts/build-bible.sh` runs `Scripts/fetch-theographic.sh`, which downloads them, checks each against the SHA-256 digest pinned in the script and stops, telling you to check it and re-pin, if one differs, and caches them in `~/Library/Caches/ReadingThroughScripture/theographic/<first twelve characters of the commit>/`, never committed, with the commit recorded beside them; a second run prints that folder at once after checking the cached tables again. The importer (`bible-importer --theographic <folder>`) writes them into `bible.sqlite` (schema version 5, `theographic_commit` in its meta table), and fails if no person is read. The app is for one person's use now; the license is share-alike, so before it is given to anyone else the converted tables must be offered under the same license (`docs/BACKLOG.md`).

## Reading plans

A reading plan is a table of weeks, each with its readings (a Wisdom chapter and an Old or New Testament passage, usually), for a group that meets weekly: this app's own church follows two, one of 67 weeks with five readings a week and no dates, one of 86 weeks with four readings (the last nine, three) and a meeting date for each. The app keeps any number of plans and follows one; **this week is the first week whose meeting date is today or later**, and the day after the meeting the next week takes over. A plan with no dates asks which week the group is on and when it next meets, and dates every week a week apart from that. Changing one week's date moves every later week by the same number of days; a week's label ("Leader Dinner", "OFF") can be changed too. After the last week's date the plan is finished.

- **Bringing a plan in.** Import… (in the plan window's toolbar, on the Plan tab's `ellipsis` menu, and in the empty state) takes a PDF or a text file; a PDF can also be dropped on the plan window. The PDF's table is rebuilt from where each word sits on the page (PDFKit, on the device, no network), so it reads this church's two layouts, a week across a page break and a name wrapped inside its cell included, and nothing else: a PDF it cannot read, or one with no text in it, says so and offers New Plan so that the plan can be typed. A text file, or text pasted into a new plan, is a line "Week 12" (with a date and a label after it, if any) to start a week and then one reading to a line (`Psalms 84; Esther 7-8`).
- **The review, which is also the editor.** Nothing is saved until the review is accepted. It shows the title, the year the dates start in (every date in a PDF is a month and a day; the app chooses the year in which they all exist and fall on one weekday, and the stepper changes it), then **To check**: a book it does not know, a chapter the book does not have, a date that does not exist or is out of order, a week numbered out of sequence, each a line that goes to the place. Each week has its number, date and label and its readings as text to edit; add, remove and drag readings, add and remove weeks. Save is off while a line cannot be read or a book is unknown. The same screen is New Plan and Edit Plan…; editing a plan in use keeps what was ticked, and a tick goes only when its reading is removed.
- **This week, on the Mac.** While a plan is followed and not finished, a band over the front page's contents shows the week: its readings side by side with a tick circle and the passages (a click on a passage opens it for reading, and Read comes forward), the plan's progress as a thin line, and The whole plan. The toolbar's `calendar` button shows the same in a popover from the reader. The plan window (View › Reading Plan, ⌥⌘P, "Reading Plan" in ⌘K, or The whole plan) lists every week down the side with its date and how many of its readings are ticked, and the chosen week's readings beside them; its toolbar has the plans menu (the one being followed is checked; Delete Plan… asks, and Edit › Undo brings the plan back with its ticks), Import…, New Plan, Edit Plan… and Change Meeting Date….
- **On the iPhone.** The Plan tab, between Read and Notes (and between them in the edge swipes: Ask, Notes, Plan, Read, Library): this week at the head and the weeks before and after in one list, a week opening in place to its readings. The `ellipsis` menu has the plans, Import…, New Plan, Edit Plan…, Change Meeting Date… and Delete Plan…, which a shake undoes.
- **Ticks.** A circle ticks and unticks a reading; nothing ticks by itself, nothing counts as behind, and a week passed with nothing ticked looks like any other.
- **Where plans live.** A plan is one record in the synced store, and each tick is one small record, so ticks made on two devices both stay and the same reading ticked twice is one tick. Which plan is followed is a synced preference (`followedPlanID`). The daily backup carries plans and ticks, and Restore… brings back the ones that are missing (it says "Restored 1 reading plan and 2 ticks."). A plan edited on two devices at once ends as the later edit.
- **The store moves forward only.** The first launch of a build that knows plans changes the store. **Never run an older build on a store the new build has used:** it does not refuse the store, it opens it and strips the plans and ticks from it (they come back from iCloud when the new build next opens it, but only what had already been sent, and not at all with sync off but for a backup). Update every device before making the first plan, and update the Release apps together, on your word. An older build on another device does leave the new records alone in iCloud: a stand-in rehearsal on 2026-11-19 confirmed it (the plan, "Rehearsal results").

The two church PDFs are never in the repository. `RealPlanPDFTests` is skipped unless `RTS_PLAN_PDFS` names the folder that holds them: `RTS_PLAN_PDFS="$HOME/Downloads" DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test --package-path Packages/ScriptureKit --filter RealPlanPDFTests` reads them where they lie, copies nothing and checks the weeks, readings, first date and flags.

## Search

⌘K on the Mac, and the Search tab on the iPhone, search the Bible, your notes, highlights, bookmarks and conversations at once, in the translation you are reading. Five forms:

| Type | Finds |
|---|---|
| `remain fruit` | Verses with both words, in any order, anywhere in the verse. |
| `abid` | Words that start with it: abide, abides, abideth, abiding. Every bare word works this way, so the results narrow as you type. Case and accents do not matter. |
| `"living water"` | Those words, next to each other, in that order (curly quotes work). |
| `love -fear` | Verses with love and without the word fear; `-"a phrase"` leaves out a phrase. |
| `beer-sheba` | A hyphen inside a word joins it; it is not a minus. |

Words are matched as written, so `love` finds love, loved, loves and loveth but not "loving" (`lov` does). A word with an apostrophe (`peter's`) finds the possessive. What the index itself understands (`OR`, `NOT`, `NEAR`, `*`, `:`) is plain text here. Your notes, highlights and conversations take the same rules; the Notes browser's own field does not (it also matches inside words and by reference).

A menu beside the results limits Scripture to the Old Testament, the New Testament, the Apocrypha (in a translation that has it), the book you are reading or any one book; it returns to Whole Bible each time ⌘K opens and, on both apps, when the field is emptied. On the Mac ⌃Tab and ⌃⇧Tab step it through Whole Bible, the testaments, the Apocrypha and the book you are reading. The count beside Scripture is the number of verses in that scope. Best match comes first; on the iPhone the full list can be put in Bible order. When Scripture finds nothing, a near spelling is offered ("Did you mean “abide”?" with its verse count) and Return runs it: it is the only row when nothing else matched, and comes last when a book, a command, a note or anything else did, so a command typed by name still runs on Return. Nothing is offered for a query with quotes, an excluded word, a word with an apostrophe or hyphen, a reference, a word with a digit, or more than twelve words. The search runs off the main thread, so typing never waits on it. Matched words are bold and underlined in every verse, quote and note line, on both apps. ⌘K is empty each time it opens, however it was closed, and shows what you read, looked up and opened lately (Recent; the newest twenty are kept on each device and never go to iCloud) and six commands; Clear Recents empties the list.

## Notes browser

The Notes window (toolbar `note.text`, View > Notes Browser, ⇧⌘N, or "Notes Browser" in ⌘K) lists every note, highlight, bookmark and assistant conversation across the Bible, newest first under a heading for each day (Today, Yesterday, then the weekday and date; each row shows its time) or in Bible order under a heading for each book (each row shows its date; the sort menu), filtered to All, Notes, Highlights, Bookmarks or Threads (and Kept versions, while there are any), and searched (⌘F) by note text, quoted text or reference ("Matt 5", "John 3:16"), or by a conversation's title, questions and replies. Return or a double-click takes the reader to the item in its translation with the card lit and the highlight outlined; Delete (or the context menu) removes an item after confirmation. Edits happen in the reader. ⌘K also offers the newest notes that match what you type.

### Exporting notes

File › Export Notes… (⇧⌘E) saves everything you have marked as Markdown; the Notes browser's Export (`square.and.arrow.up`) saves what the list shows, so filter to Bookmarks or search first to export only those. The save panel chooses the layout, One file (`Bible Carrel Notes 2026-11-01.md`) or One file per book (a folder of that name with a `README.md` and a file per book, replacing a folder already there), and whether to include conversations. Either way the items run in canon order under a heading per book and per chapter; a note or highlight quotes its words the way Copy with Reference does, as a blockquote (`> “Blessed are the poor in spirit” — Matthew 5:3 (ESV)`), then the note's text as written and a line naming the kind, color and date; a bookmark quotes its verse in the translation being read, and a conversation gives each turn under its speaker.

### Kept versions

Two devices that change one note's text before they have synced used to leave one text and lose the other. Now both are kept. The note shows the text that won, and under it a quiet mark, `square.on.square` and "2 versions"; click it (on the phone, open the note and tap it) to see both texts, each with its device ("Mac", "iPhone") and time. Three choices settle it: **Use This One** (the note takes these words and the other text is kept), **Keep Both in the Note** (the kept text goes under the note's) and **Discard** (the version is removed; Edit › Undo brings it back). Nothing alerts you and nothing is red; leave it as long as you like. Edits made after reading the other device's text keep nothing, because nothing clashed.

How it works: Apple's sync keeps one of two clashing texts and destroys the other everywhere, so the device that wrote the lost text is the only one that can save it. Every save of a note writes a small file per note under `LastTexts` (`LastTexts-<name>` for a named store) beside the store, before the save, and after the next import from iCloud the device keeps any text of its own that was replaced, as a kept version (a record of its own in iCloud, so it reaches your other devices). A note carries three new values: a mark naming the version (a digest of the text, never the text), what that sitting started from and the kind of device ("Mac", "iPhone", "iPad", never its name). A note deleted on one device and edited on another leaves the edited text as a **kept version with no note**, listed only under Kept versions in the Notes window and the phone's Notes tab; Restore as a Note puts it back on its passage and Discard removes it. A deletion leaves a small marker (the note and digests of its texts, never text) that goes after ninety days, so a delete made after reading the last text keeps nothing. Deleting a note that shows "2 versions" leaves the other text under Kept versions until you discard or restore it. Records that share an identity (two restores of one backup can make them) are read as one and not deleted; only a note's copy whose text differs is kept first.

Known limits: one device typing back its own earlier text exactly while another device edits can lose that text (sight is by device and digest, which closes every other case; the backlog has this one). A journal file outlives a store that was reset by hand or emptied by an account change, and then turns each of its entries into a kept version with no note. An older build still in use on one device leaves a text under an unchanged mark and a delete with no marker, and both are kept from, at the cost of one discard.

### Export All Data and Import Data

File › Export All Data… (and the same on the phone, Settings › General › Your Data) writes everything you have made to one JSON file, `Bible Carrel Data 2026-11-19.json`: colors, highlights, notes (with their three version values), kept versions, bookmarks, prompts, reading plans, ticks and assistant conversations. A switch, Include conversations, leaves the conversations out on the Mac (the phone always includes them). The file leaves out your API keys (they stay in the Keychain), the synced and per-device preferences, deletion markers, the journal of last texts and the backups. File › Import Data… (the phone's Import Data…) adds what the file has that this device does not and **never edits or deletes** anything: a second import adds nothing, a record you deleted comes back, a note whose text differs from the file's keeps the file's text as a kept version (a text the note was edited from counts as already here, but only for one sitting of editing: a note edited twice on one device since the export gets the file's old text as a kept version, which you can discard), and a file that is damaged, not this app's or from a newer version changes nothing and says why. The result is one sentence: "Added 12 notes and 3 highlights. 2 notes have another version kept. 40 were already here." The import is offered when Restore… is (sync off, or once the account is available and an import has finished) and runs in one pass on the main thread, so a very large store may stall for a moment.

The file's format, version 1 (`DataFile`; every `id` is the record's uuid; a `?` is left out when nil; dates are ISO 8601 UTC with milliseconds; a reader ignores keys it does not know, reads a missing kind as empty, and refuses a `version` above 1):

| Key | Each record |
|---|---|
| top level | `format` (`bible-carrel-data`), `version`, `exportedAt`, `app`, then the nine kinds below |
| `colors` | `id`, `name`, `lightHex`, `darkHex`, `sortOrder`, `isDefault`, `builtInKey?` |
| `highlights` | `id`, `book`, `chapter`, `verse`, `endVerse`, `startOffset`, `endOffset`, `translationID`, `colorID?`, `quotedText`, `createdAt`, `modifiedAt` |
| `notes` | `id`, `body`, `createdAt`, `modifiedAt`, `scope`, `book`, `chapter`, `verse`, `endVerse`, `translationID`, `quotedText`, `highlightID?`, `sourceThreadID?`, `versionMark?`, `versionAncestry?`, `deviceKind?` |
| `keptVersions` | `id`, `noteID?`, `body`, `writtenAt`, `deviceKind`, `book`, `chapter`, `verse`, `endVerse`, `translationID`, `quotedText`, `startOffset`, `endOffset` |
| `bookmarks` | `id`, `book`, `chapter`, `verse`, `createdAt`, `label?` |
| `prompts` | `id`, `title`, `summary`, `body`, `scope`, `section?`, `isEnabled`, `sortOrder`, `isBuiltIn`, `builtInKey?`, `outputKind` |
| `plans` | `id`, `title`, `createdAt`, `modifiedAt`, `weeks` (the stored plan JSON, embedded as it is, carrying its own `"v"`) |
| `ticks` | `id`, `planID?`, `readingID?`, `tickedAt` |
| `conversations` | `id`, `scope`, `book`, `chapter`, `verse`, `endVerse`, `startOffset`, `endOffset`, `translationID`, `quotedText`, `title`, `createdAt`, `updatedAt`, `messages` |
| a message | `id`, `role`, `content`, `createdAt`, `providerID`, `modelName`, `attachedReference?`, `displayText?`, `providerHost?`, `finishReason?`, `savedNoteID?` |

A file over 256 MB is refused as damaged, unread.

## Study assistant

The assistant answers beside the page, in the inspector where the notes column sits (the cross-fade is a cut with Reduce Motion on). Three ways in:

- **Ask About This Passage** on a selection's right-click menu opens it on that phrase with the selection prompts listed under About the passage (Explain this passage, Define the words, Compare translations); click one to send it, or type a question.
- **Ask About This Chapter** on the running head's right-click menu opens it on the chapter in view with the chapter prompts in three sections: Get oriented (Catch me up, Set the scene, Summarize this chapter, Outline this chapter), Dig in (Name the key themes, Find cross-references, Identify people and places, Explain the hard verses, Study the key words) and Take it with you (Write reflection questions, Suggest a memory verse). Each appears as a tile with its title over a sentence on what comes back (one column at the panel's default width, two once it is dragged wider than about 400 pt); prompts you add are listed last, under Your prompts. A plain click on the running head goes back to the book's chapter grid.
- **⇧⌘A**, the toolbar `sparkles` button, Assistant › Show Assistant or "Ask the Assistant" in ⌘K opens it on the selection when text is selected; otherwise it reopens the open conversation, or asks "Include where you are?" with buttons for the chapter, the book and No context. A book conversation follows you from chapter to chapter and tells the model when you move; No context sends nothing about where you are. The `plus` menu starts a new conversation (on the chapter, the book or No context), as does Assistant › New Conversation… (⌃⌘N), which always asks "Include where you are?"; Escape or `xmark` goes back to Notes.

Return sends, Shift-Return starts a new line, Stop ends a reply early and keeps what arrived. Each reply names who answered (`On-device`, `Claude · claude-opus-5-5`, `OpenAI · gpt-5`, or the custom endpoint's host). A reply is one selectable text, so a drag selects across its paragraphs; a reply that ended early says so beside who answered (Stopped, Cut short, Declined partway, Ended early). Copy puts the reply on the pasteboard and shows a checkmark for a moment; **Add as Note** saves it under its question (`**Q:** …`) as a note on the selection (appended to the note already there, or on a new underline) or, for a chapter, book or general conversation, as a chapter note, then opens it in the column for editing. Add as Note becomes **Show Note** once a reply is saved (and Add as Note again if that note is deleted). **Try Again** (⌘R) resends a question that got no answer, after a failure or a stop, to the same provider when Settings still route there (otherwise to whoever answers now), and shows the panel if it was hidden.

The Assistant menu holds the panel's commands with their shortcuts:

| Command | Shortcut |
| --- | --- |
| Show Assistant / Show Notes | ⇧⌘A |
| New Conversation… | ⌃⌘N |
| Try Again | ⌘R |
| Copy Last Reply | ⇧⌘C |
| Add Last Reply as Note | ⇧⌘S |
| Stop Answering | ⌘. |

Apple's on-device model answers by default. Its window is about 4,096 tokens, so a request is sent on-device only when it estimates under 3,000 tokens (four characters a token); longer ones go to the first cloud provider with a key (Claude, then OpenAI, then a custom endpoint), and without one the panel says the passage is too long and offers Settings. Catch me up sends only the first and last five verses of the previous chapter when the whole one would not fit on-device; Compare translations lists at most three other translations on-device. Settings › Assistant sets who answers (Automatic, On-device, Claude, OpenAI, Custom endpoint), the keys, the model names (`claude-opus-5-5` and `gpt-5` by default) and a custom OpenAI-compatible endpoint (Ollama, LM Studio). A key is saved as you type. Keys are stored in the Keychain as synchronizable items in the data-protection keychain (service: the build's bundle ID, `com.matthewfurr.ReadingThroughScripture` or `….dev`; account `llm.<provider>`), so they travel through iCloud Keychain. A key an older build saved in the login keychain is still read, and is moved to the synchronizable keychain at launch; the first read of such a key may show one macOS keychain prompt, because the old item was saved by a differently signed build.

Settings › Prompts edits the prompts, grouped under the same sections as the panel: enable or hide, rename, edit the summary (a sentence or two shown under the title) and the text, reorder within a section by the handle or with Move Up and Move Down in a row's context menu, add your own, and restore an edited built-in's title, summary and text. Prompts saved by an earlier version are brought up to date the first time the app opens: a built-in still at its original title and text takes the new title (Overall summary becomes Summarize this chapter, and so on), while one you renamed or whose text you edited keeps its title; every built-in gains its summary and section; and if you never reordered the list, the built-ins take the new order, with your own prompts after them. A prompt's text may use `{{reference}}`, `{{chapter_text}}`, `{{translation}}`, `{{selection}}`, `{{previous_chapter_text}}` and `{{other_translations}}`; anything else is sent as typed.

Conversations are saved in the markup store with their chapter. The `clock` menu lists this chapter's (and this book's) conversations and can delete the open one; the Notes browser lists them all under Threads, and showing one opens its chapter and the conversation. Deleting a conversation can be undone with ⌘Z.

## Sync and backups

Everything you make is kept in a SwiftData store mirrored to your private iCloud database: highlights, notes, bookmarks, assistant conversations and their messages, prompts, highlight colors, reading plans and the ticks in them, and the kept versions and deletion markers of the notes (eleven kinds of record). Each record keeps its own identity across devices, and when two devices change the same record the later change wins, except for a note's text, where the text that lost is kept as a version (see Kept versions). iCloud holds the two new kinds and a note's three new values; **the device alone** holds the journal of the last text it wrote for each note (the `LastTexts` folder beside the store), which is never in iCloud. The Bible text never syncs.

The store is `~/Library/Application Support/ReadingThroughScripture/Sync/<container>-<Environment>/Markup.store`, one directory for each iCloud container and environment so one file is never mirrored to two cloud databases:

- Release: `Sync/iCloud.com.matthewfurr.ReadingThroughScripture-Development/`
- Debug: `Sync/iCloud.com.matthewfurr.ReadingThroughScripture.dev-Development/`
- A build with no iCloud entitlement (an unsigned build, the tests): `Local/Markup.store`, and sync is off.

The app learns which container and environment it uses from its own signature, so the build settings cannot disagree with what it does. The old local store, `ReadingThroughScripture/Markup.store`, is copied into the Release build's synced store once, on its first launch, record by record; the old file is never opened for writing and stays exactly as it was. `ReadingThroughScripture/Markup.legacy-imported`, beside the old store, marks that the copy is done; every environment of the Release container shares it, so a later move to another environment never copies the old store again. (A Debug build's rehearsal copy, `Legacy.store`, keeps its marker in its own synced directory.)

On a new store with an iCloud account, the app waits for the first import from iCloud (or 15 seconds) before it adds the default colors and built-in prompts, so a second device takes what the cloud has. If two devices still each made a default, they merge after every import, keeping your changes; two bookmarks on one verse become one, and so do two ticks on one reading (the earlier stays).

These preferences travel through the iCloud key-value store, mirrored onto the same `UserDefaults` keys: `readingPosition`, `readingPosition.translationID`, `defaultTranslationID`, `showNotelessHighlights`, `finishEditingWithReturn`, `assistantProvider`, `anthropicModel`, `openAIModel`, `compatibleBaseURL`, `compatibleModel`, `compareTranslationIDs` (the translations Compare Translations shows), `showDates` and `datesNoticeAnswered` (whether the Library shows dates, and whether its one-time notice about them has been answered), `followedPlanID` (the reading plan being followed), and the reader's taste settings `readerPageStyle`, `readerPageFace`, `readerVerseLayout`, `readerShowsVerseNumbers`, `readerShowsSectionHeadings` and `readerJustified`. A reading position from another device moves the reader only if it arrives while the app is in the background or before you have moved in this launch, and never while you are looking something up; Back returns from it. Everything else stays with each device: text size, line spacing, column width, appearance, whether the notes column shows, the Notes browser's sort and filter, the export choices and the Settings tab.

Signing out of iCloud empties the synced store; that is how Apple's sync works and there is no way to change it. Your notes come back when the same account signs in again, but anything not yet uploaded is lost. Without an account the app opens as usual, adds the defaults at once, keeps what you make on this Mac and says so in Settings.

A backup of the store is taken once a day, at launch or when the app comes to the front and today's is missing (or holds no highlights and no notes while the store has some, as when it was taken before the old store's import), to `Backups/yyyy-MM-dd.store` beside the store (`Backups-<name>/` for a named store); the newest seven are kept. It is a single SQLite file written with SQLite's online backup API, so it is safe while the app runs. Settings › General › Restore… brings back every record in a backup that the store no longer has (kept versions included; deletion markers are not restored) and changes nothing else: it never edits or deletes, so it asks no confirmation, and the restored records then sync. Putting an old store file in place of the live one does not work, because iCloud replays its deletions onto it. The daily backup counts highlights and notes only, so a store that holds reading plans and no highlights or notes is taken as empty: its backup is skipped while the newest one on disk has marks in it.

**The store moves forward only.** The first launch of a build that knows kept versions changes the store (a note gains three values, and two kinds of record are added). **Never run an older build on a store this build has opened:** the older build does open it, and strips the new kinds and the three values from it; they return from iCloud when this build next opens it, but only what had already been sent, and not at all with sync off but for a backup. A rehearsal on 2026-11-19 with a store from before this project confirmed that this build opens such a store and keeps its notes. The Release apps are not updated by this project: update them together, on your word, and never roll one back. A build that refuses a store a newer build has used is on the backlog.

A second device joins by installing the app, signing in to the same iCloud account and waiting for the first import. Never copy a store file between Macs; let iCloud bring the notes.

The reading window shows nothing about sync unless it has failed for a day because iCloud is full or for a reason other than being offline: then an iCloud button (`exclamationmark.icloud`) at the head of the toolbar's right-hand group opens Settings › General, and its help tag names the day sync last worked.

## iPhone

The iPhone app is the same reader with the same synced notes, in the `ReadingThroughScripture-iOS` scheme (`Apps/iOS`, sharing `Apps/Shared` and the package with the Mac). It is laid out for the iPhone only; the iPad comes later.

Build it for the simulator with:

```bash
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcodebuild -workspace ReadingThroughScripture.xcworkspace -scheme ReadingThroughScripture-iOS -configuration Debug -destination 'platform=iOS Simulator,name=iPhone 18 Pro Max' -derivedDataPath Build/DerivedData -allowProvisioningUpdates build
```

The app is `Build/DerivedData/Build/Products/Debug-iphonesimulator/ReadingThroughScripture.app`; install it with `xcrun simctl install booted <app>` and launch it with `xcrun simctl launch booted com.matthewfurr.ReadingThroughScripture.dev`. In a Debug build, `-phoneSeed YES` fills an empty store with a fixed sample in John 15 (a highlight with a note, a highlight and a bookmark, a note, and one conversation). Debug and Release keep the Mac's two identities.

`Scripts/install-phone.sh` builds for the phone, signs it with the team and installs it there:

- `Scripts/install-phone.sh debug` installs the Debug build (the `.dev` identity).
- `Scripts/install-phone.sh release --go-live` installs the Release build, the one that holds your real notes. Without `--go-live` it refuses before anything is built.

The Release build was installed on the iPhone on 2026-11-11 with `Scripts/install-phone.sh release --go-live`. It uses the same bundle ID and iCloud container as the Mac's Release build, and its notes arrive from iCloud on first launch.

With no device named it uses the one paired iPhone that `xcrun devicectl list devices` reports; name one as the last argument when more than one is paired.

Settings (the `ellipsis` menu) ends with About, the same list of sources as the Mac's. The tabs are Read, Plan, Notes and Ask, with the search button beside them:

- **Read** shows the chapter. The bar has the library (`books.vertical`; Old Testament and New Testament over a list of the books, where a tapped book shows its chapters under its name; it opens on the book you are reading, with each Testament's books under their group's name, and a tapped book showing People, Places and About beside its BibleProject video; see The Library), the running head (the chapter and the translation, in the bar's title), the highlighter and an `ellipsis` menu whose page style, text size, line spacing and appearance (Light, Sepia, Dark) are rows of buttons, then the translation, Notes in This Chapter and Settings. A verse with a note or bookmark carries a mark in the right margin; tap a note's mark to open it. Notes on a chapter itself show as a counted paper mark on that chapter's opening line, which opens Notes in This Chapter. Every chapter ends with Previous and Next links to the chapters either side, crossing into the neighboring book at either end. Tap a verse to select it with the menu over it, or press and hold to select words; the menu colors, notes, bookmarks, copies, shares or asks about them. It leads with one circle in a color (the highlight's when the words are inside one, otherwise the pen's); tap it for the list of your colors. The actions after it are symbols; the list behind the menu's chevron names each one, Look Up and Translate last.
- **The pen.** Tap the highlighter and the tab bar becomes a row of your colors. Hold a word for a moment (0.15 s) and drag to paint; a drag that starts moving scrolls instead. Tap a mark to select it: handles at its ends resize it, and the menu under it leads with the mark's color (a color chosen there recolors it and becomes the pen's), then adds a note, bookmarks the verse, asks about it or deletes it. Done turns the pen off. It is hidden while VoiceOver runs, since the selection menu does everything it does.
- **Notes** lists everything marked, narrowed by three menus: how far back, what kind (Everything, Notes, Highlights, Bookmarks, Conversations, and Kept versions while there are any) and which order (Newest first, Bible order). A swipe deletes; shake or a three-finger swipe undoes. The `ellipsis` menu exports what is listed as Markdown through the share sheet.
- **Ask** is the assistant, with the Mac's prompts and conversations. Ask About This Passage on a selection opens it over the page.
- **Search** is one field for everything: a reference or book, the words of the Bible, your notes and your conversations, grouped, with chips that narrow to one kind (the Library's People and Places among them: a name typed opens that person's or place's page for the whole Bible, pushed inside Search). It takes the forms under Search above, with menus for where to search (Whole Bible, a testament, a book) and, on the Scripture chip, the order. With nothing typed it lists what you read and looked up lately (Recent, with Clear); it has no commands. With a hardware keyboard ⌘K opens it from any tab, and ⌘[ and ⌘] go back and forward on the Read tab.

Looking something up keeps your place, as on the Mac: a row in Notes, a mark or verse in search, or a reference in an answer opens the passage with your chapter's name at the top left as the way back. Reading on with Next or Previous, or Read From Here in the `ellipsis` menu, makes the passage your place; so does scrolling five lines or more from a jump inside the chapter you are reading (not for a passage opened from the Library: see The Library). A passage opened from the Library names the person, place or view you came from as the way back.

Settings › General has Your Data after Backups: Export All Data… (the share sheet) and Import Data… (the file picker). A note with more than one version shows the mark under its text in the note sheet and the Notes tab; tapping it opens the versions (a note's, on a page pushed inside the sheet; a text with no note, in a sheet of its own), and a swipe on a kept version's row discards it (a shake undoes it).

Your notes, the reading position and the synced preferences travel between the Mac and the phone. Some things stay with each device: text size, line spacing, column width, appearance, the Notes tab's time filter and the pen's color.

## Running the tests

```bash
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test --package-path Packages/ScriptureKit
```

No test touches real iCloud, the real Keychain, the iCloud key-value store, the network or anything under `~/Library/Application Support/ReadingThroughScripture`; stores in tests are in memory or in the temporary directory.

## Layout

- `Packages/ScriptureKit` — all shared Swift code: `ScriptureData` (read API, canon catalog, reference parser), `ScriptureModel` (the SwiftData models and store; sync configuration, store location, the sync monitor and coordinator, store copy, backups and seed merges), `ScriptureLLM` (providers and the Keychain), `ScriptureUI` (front page, reader, command palette, navigation model, reading position, preference sync, the sync status and backups models, Settings), `BibleImporterCore` (JSON to SQLite), and the `bible-importer` CLI.
- `Apps/Mac` — the macOS app target (window, toolbar, menus, `AppSync` and the Debug-only `SyncProbe`), its entitlements and its Xcode project; `ReadingThroughScripture.xcworkspace` at the root ties it to the package.
- `Apps/iOS` — the iPhone app target and its Xcode project; `Apps/Shared` — the startup and sync code both apps use.
- `Scripts/` — fetch and build scripts, `install-app.sh` and `install-phone.sh`.
- `docs/superpowers/` — design specs and implementation plans.
